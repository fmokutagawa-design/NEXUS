# Azuki由来 差分編集履歴 設計書

## 目的

14万字級原稿で本文全文を最大100件保持する現在のUndo/Redoを、Azukiの考え方を参考にした差分履歴へ置き換える。保存済み地点を履歴上で識別し、Undo/Redoやモード切替が古い本文の自動保存を誘発しないようにする。

AzukiのC#コードやWinForms描画系を直接組み込まず、zlibライセンス表示を保ったうえで設計概念のみをJavaScriptで独立実装する。

## 編集操作モデル

すべての本文変更を次の置換操作として表す。

```text
EditAction = {
  start,
  deletedText,
  insertedText,
  beforeSelection: { anchor, focus },
  afterSelection: { anchor, focus },
  source,
  timestamp
}
```

Undoは`insertedText`を`deletedText`へ戻し、Redoは逆操作を行う。操作適用関数は純粋関数とし、DOM更新、React通知、保存要求を内部から行わない。

## 操作のグループ化

- 連続タイピングは時間だけでなく、隣接位置と操作種別が一致した場合にまとめる
- IME変換中は履歴を確定せず、`compositionend`で一操作として確定する
- 検索置換、AI挿入、ルビ挿入は明示的な一操作としてまとめる
- ファイル切替、外部再読込、スナップショット復元は通常編集履歴と区別する

## 保存地点

履歴には単なる`dirty`真偽値ではなく、保存済みリビジョンIDを保持する。

- 保存成功後にのみ現在の履歴位置を`savedRevision`へ設定する
- Undoで保存地点へ戻った場合は未保存なしと判定する
- Redoで保存地点から離れた場合は未保存ありと判定する
- 外部編集検知時は保存地点を勝手に移動しない
- 「変更を保持して戻る」は履歴も本文も変更せず、表示モードだけを変える

## 保存系との境界

履歴操作は本文を画面へ適用しても、自動保存を直接開始しない。変更元を`typing`、`undo`、`redo`、`replace`、`external-reload`、`snapshot-restore`に分類し、保存可否は既存の保存安全層が判断する。

外部編集競合中、スナップショット復元後、明示的な再読込直後は自動保存を停止する。Undo/Redoで古い本文になったことだけを理由にディスクへ保存しない。

## マーカー追随

検索結果・校正指摘は本文そのものへ埋め込まず、開始・終了位置を持つ範囲として管理する。編集操作ごとに次の規則で位置を更新する。

- 編集範囲より前のマーカーは変更しない
- 編集範囲より後ろのマーカーは文字数差だけ移動する
- 編集範囲と重なるマーカーは無効化し、再解析対象にする

初期段階では検索・校正マーカーだけを対象とし、描画エンジンやテキストバッファ全体の置換は行わない。

## メモリ境界

- 履歴件数だけでなく、差分文字列の合計バイト数に上限を設ける
- 巨大な一括置換は一操作として保持するが、上限超過時は最古の操作から破棄する
- 現在本文は従来どおり一つ保持し、独自のrope/piece table導入は別課題とする

## テスト

- 挿入、削除、置換のUndo/Redo
- IME一操作化とカーソル復元
- 置換プレビュー確定を一回でUndoできること
- 保存地点へ戻った場合のdirty判定
- 外部編集競合中にUndoしても保存要求が発生しないこと
- 「変更を保持して戻る」で本文と履歴が不変であること
- マーカーの移動・無効化
- 14万字本文で一文字編集を100回行った際、全文100部を保持しないこと

## 移行

最初に純粋な差分履歴モジュールを追加し、既存フックの公開インターフェースを維持したまま内部を差し替える。Editorへの接続はファイル切替、IME、置換、Undo/Redoの回帰テストが揃ってから行う。異常時に旧全文履歴へ自動的に戻す仕組みは、二重履歴による不整合を招くため設けない。

## 完了条件

- 通常入力の履歴が全文スナップショットを保持しない
- Undo/Redo後の本文とカーソルが一致する
- 保存済み地点の判定が履歴移動に追随する
- Undo/Redo、モード切替、外部競合が無確認のファイル保存を発生させない
