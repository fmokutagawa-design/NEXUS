# NEXUS AI編集依頼情報 設計

## 目的

NEXUSで保存した原稿をCodexやChatGPTへ編集依頼するとき、旧版・同期前の版・別ファイルを誤って編集する事故を防ぐ。

依頼者が本文中の修正位置を特定できない「全文精査」「この問題を全体から直す」といった依頼でも、AIが対象範囲と依頼時点の版を機械的に照合できる情報をNEXUSから生成する。

## 採用する方式

「AI編集依頼をコピー」画面で対象範囲を選び、対象ファイルの目録と安全指示をクリップボードへ出力する。

対象範囲は次の3種類に限定する。

1. 現在のファイル
2. 複数ファイル（利用者が明示選択）
3. フォルダ直下の対応ファイル

フォルダ指定は再帰しない。サブフォルダ内の旧稿、資料、バックアップを意図せず編集対象に含めないためである。

## URLと識別情報の役割

- フォルダURL: AIが対象を探す場所。作品ごと、または依頼ごとに利用者が登録する。
- ファイル名: フォルダ内で探す対象。
- ローカルパス: NEXUSとローカルCodexが同じコンピュータ上にある場合の直接参照先。外部へ共有する可能性があるため、コピー前に含めるか選択できるようにする。
- SHA-256: 依頼時点のファイル内容が一致しているかを確認する識別値。
- 文字数・更新日時: 人が版違いに気づくための補助情報。正本判定には使用しない。

Google DriveのフォルダURLから、配下ファイルの個別Drive URLを推測しない。Drive API連携を行わない初期版では、フォルダURLとファイル名で探索し、取得した内容のSHA-256で一致を確認する。

## 生成される依頼情報

```text
[NEXUS AI編集依頼]
対象種別: フォルダ直下
対象フォルダ: 最終4版
フォルダURL: https://drive.google.com/drive/folders/...
生成日時: 2026-09-08T00:00:00+09:00

[対象ファイル目録]
1. 01_序章.txt
   文字数: 12345
   更新日時: 2026-09-08T00:00:00+09:00
   SHA-256: ...
2. 02_第一章.txt
   文字数: 23456
   更新日時: 2026-09-08T00:00:00+09:00
   SHA-256: ...

[依頼内容]
（利用者が入力した自由文）

[必須の安全手順]
1. 編集前に対象ファイルを取得する。
2. 各ファイルのSHA-256を計算し、目録と照合する。
3. 一つでも一致しない、取得できない、同名ファイルが複数ある場合は編集しない。
4. 不一致のファイル名、取得したSHA-256、想定SHA-256を報告して確認を求める。
5. 一致確認後も、書き込み直前に対象ファイルが変化していないことを再確認する。
```

## UI

既存のファイルツリーまたはツールバーから「AI編集依頼をコピー」を開く。ダイアログには以下を置く。

- 対象: 現在のファイル／複数ファイル／フォルダ直下
- 対象選択欄
- フォルダURL（保存済みなら自動入力、編集可能）
- ローカルパスを含める（初期値はオン。コピー内容のプレビューで確認可能）
- 依頼内容
- 生成内容のプレビュー
- 「クリップボードへコピー」ボタン

対象ファイルが未保存の場合は生成を禁止し、「先に保存してください」と表示する。NEXUS画面上の未保存本文をハッシュ対象にはしない。AIが取得するディスク上の内容と一致しない可能性があるためである。

## データの保存

フォルダURLは作品設定に保存する。作品が特定できない通常フォルダの場合は、そのローカルフォルダパスをキーに端末内設定へ保存する。

保存するのはURLのみで、過去のファイル目録やハッシュを継続保存しない。目録は依頼作成時にディスクから毎回再生成し、古い依頼情報の再利用を避ける。

URLが空でも、ローカルパスを含む依頼情報は生成できる。URLとローカルパスの両方がない場合は、AIが対象を取得できないことを警告する。

## ファイル収集規則

- 現在のファイル: `activeFileHandle` が指す一つの保存済みファイル。
- 複数ファイル: ファイルツリーで利用者が明示選択した保存済みファイル。
- フォルダ直下: 指定フォルダ直下にあるNEXUS対応テキストファイルのみ。ディレクトリは除外する。
- `.nexus` 作品の「作品全体」を選ぶ場合は、フォルダ列挙ではなく `manifest.json` の `segments` 順を使用する。目録の順序も章順にする。
- 同名ファイル、読込失敗、ハッシュ計算失敗が一つでもあれば生成を中止し、該当項目を表示する。

## ハッシュ規則

SHA-256はディスクから読み込んだファイルの生バイト列に対して計算する。改行コード、文字コード、末尾改行の違いも変更として検出する。

初期版では本文正規化ハッシュを設けない。AI側が生ファイルを取得できず、抽出・正規化された本文しか扱えない環境では厳密照合できないため、「照合不能」として編集を止める。曖昧な一致を安全確認として扱わない。

## 競合防止との関係

この機能は「AIへ正しい版を渡す」入口の防護であり、NEXUSの保存時競合防止とは独立して動作する。

- 依頼作成時: ディスク内容から目録を生成する。
- AI編集前: AI側が目録と取得内容を照合する。
- AI書き込み時: AI側が書き込み直前の再照合を行う。
- NEXUS保存時: 既存の外部変更検出により、AIが変更したファイルへの盲目的な上書きを拒否する。

クラウド同期の遅延による旧版化を完全に防ぐには、Google Driveへのアップロード完了確認が別途必要である。初期版はDrive API認証を導入せず、クラウド同期状態を「同期済み」とは表示しない。

## エラー処理

- 未保存変更あり: コピー生成を禁止し、保存を案内する。
- 対象なし: 生成を禁止する。
- ファイル読込失敗: 対象名と理由を表示し、部分的な目録はコピーしない。
- URL不正: `https://drive.google.com/drive/folders/<ID>` 形式は正規化し、それ以外は警告する。ただしローカル専用依頼としてURLを空にする選択は許可する。
- クリップボード失敗: 生成内容を選択可能なテキストとして残す。

## 構成案

- `src/utils/aiEditRequestManifest.mjs`: 対象検証、SHA-256、目録生成、依頼文整形を行う純粋ロジック。
- `src/components/AIEditRequestModal.jsx`: 対象選択、URL、依頼文、プレビュー、コピー操作。
- `src/hooks/useAIEditRequest.js`: ファイル収集、ディスク読込、作品設定との接続。
- 既存の作品設定または永続設定: フォルダURL保存。
- `App.jsx`／ファイルツリー: 起動導線と選択対象の受け渡しのみ。

ハッシュ計算とファイル列挙は既存のElectronブリッジ／ファイルシステム抽象を通す。Reactコンポーネントに直接ファイルI/Oを埋め込まない。

## テスト

### 単体テスト

- 一文字変更でSHA-256が変化する。
- 対象順が入力順およびmanifest順を保持する。
- フォルダ指定がサブフォルダを含めない。
- 同名、読込失敗、ハッシュ失敗で全体が中止される。
- DriveフォルダURLから余分なクエリを除去できる。
- 安全手順が生成文から欠落しない。

### 結合テスト

- 現在ファイル、複数ファイル、フォルダ直下、`.nexus`作品全体で正しい目録を生成できる。
- 未保存状態では生成できない。
- 保存済みURLが作品ごとに復元される。
- コピー失敗時に本文を手動コピーできる。

### 回帰確認

- 通常保存、オートセーブ、リーダーからの編集、外部変更競合表示に影響しない。
- 14万字級ファイルのハッシュ計算中も入力欄をブロックしない。

## 初期版の対象外

- Google Drive APIへのログインと同期完了確認
- Driveフォルダ内ファイルIDの自動取得
- AI側への自動送信または自動編集
- サブフォルダの再帰走査
- 自動マージ
- 過去の依頼目録管理
